# ML-модуль Cargora: прогноз загруженности пунктов пропуска

Собственная модель машинного обучения, которая прогнозирует загруженность
четырёх ключевых пунктов транзита Каспийского коридора (порт Актау,
КПП «Болашак», КПП «Тажен», ж/д узел Бейнеу) на 48 часов вперёд.

Прогноз используется платформой в двух местах:

- `GET /api/forecast` — почасовой прогноз по всем пунктам + рекомендация
  оптимального 4-часового окна прохождения;
- `POST /api/ai-route` — при подборе паромного рейса прогноз порта Актау
  подмешивается в рекомендацию, и отправитель сразу видит, когда выгоднее
  привезти груз в порт.

## Архитектура

```
ml/generate_dataset.py      симулятор транзитного потока (2 года, 71 040 наблюдений)
        ↓
ml/data/checkpoint_traffic.csv
        ↓
ml/train.py                 GradientBoostingRegressor (scikit-learn)
        ↓                   + метрики против бейзлайна + графики
lib/forecast-model.json     экспорт деревьев (98 КБ)
        ↓
lib/forecast.ts             инференс на TypeScript — работает на Vercel
                            без отдельного Python-сервера
```

## Данные и методология

Открытых почасовых данных по загруженности КПП Мангистауской области не
существует, поэтому датасет построен **симулятором** (трек хакатона явно
допускает "Synthetic datasets generated from simulation tools").
Симулятор воспроизводит известные из практики перевозчиков процессы:

| Фактор | Реализация |
|---|---|
| Суточный профиль | ночь тихая, пики 8–11 и 14–18; порт работает 24/7 (сглажен) |
| Недельная сезонность | грузопоток проседает в субботу и воскресенье |
| Годовая сезонность | пик в октябре (зерно, стройматериалы), спад в январе |
| Погода | AR(1)-ветер: шторм >13 м/с копит очередь в порту; мороз <−12 °C замедляет досмотр на автомобильных КПП |
| Праздники РК | таможня в сокращённом составе → очередь растёт |
| Инциденты | случайные события (усиленный досмотр, поломки) — **латентный фактор**, модель его не видит; честный источник неустранимого шума |

## Модель

- **GradientBoostingRegressor** (220 деревьев, глубина 3, lr 0.08, subsample 0.9)
- Признаки: час (sin/cos), день недели, выходной, сезон (sin/cos),
  ветер, температура, праздник РК, пункт пропуска (one-hot)
- Одна модель на 4 пункта: общие погодные/календарные закономерности +
  индивидуальные профили пунктов
- Валидация: **временной сплит** (без утечки) — тест с 2026-03-01

## Результаты (тест: март — июнь 2026, 9 792 наблюдения)

| Метрика | Наша модель | Бейзлайн (средняя по часу недели) |
|---|---|---|
| MAE | **4.04 %** | 6.85 % |
| RMSE | **5.81 %** | 8.10 % |
| R² | **0.896** | 0.797 |

Модель снижает ошибку прогноза на **41 %** относительно климатологического
бейзлайна. Графики: `figures/forecast_vs_actual.png`, `figures/feature_importance.png`.

## Инференс в продакшене

Деревья экспортируются в `lib/forecast-model.json`, проход по ним реализован
вручную на TypeScript (`lib/forecast.ts`):
`prediction = init + learning_rate * Σ tree(x)`.

На вход подаётся **реальный прогноз погоды** для района Актау
(Open-Meteo, без API-ключа); при недоступности — климатологический фолбэк.

Эквивалентность инференса проверяется сверкой:
`parity_check.py` (sklearn) ↔ `parity-check.ts` (TypeScript) — предсказания
совпадают до округления.

## Воспроизведение

```bash
cd ml
python -m venv .venv
.venv/Scripts/activate        # Windows; на Unix: source .venv/bin/activate
pip install -r requirements.txt

python generate_dataset.py    # ml/data/checkpoint_traffic.csv
python train.py               # метрики, графики, lib/forecast-model.json
python parity_check.py        # сверка с TypeScript-инференсом
```
