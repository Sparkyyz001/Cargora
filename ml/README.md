# ML-модуль Cargora: прогноз спроса на перевозки по направлениям

Собственная модель машинного обучения, которая прогнозирует **число заявок
на перевозку в час** по десяти ключевым направлениям внутри Мангистауской
области на 48 часов вперёд.

Прогноз используется платформой, чтобы показать перевозчику, где не хватает
машин: `GET /api/forecast` отдаёт почасовой прогноз по направлениям и
расчёт незакрытого спроса.

## Архитектура

```
ml/generate_dataset.py       симулятор спроса (2 года, 177 600 наблюдений)
        ↓
ml/data/direction_demand.csv
        ↓
ml/train.py                  GradientBoostingRegressor + метрики против бейзлайна
        ↓
lib/forecast-model.json      экспорт деревьев (98 КБ)
        ↓
lib/forecast.ts              инференс на TypeScript прямо в Next.js
```

Отдельный Python-сервис в проде не нужен: деревья выгружаются в JSON,
а проход по ним переписан на TypeScript. Прогноз считается в обычном
route handler на Vercel.

## Почему симулятор

Открытых почасовых данных о числе заявок на перевозку внутри Мангистауской
области не существует — БНС такую статистику не публикует. Датасет строится
симулятором, что прямо допускается треком («Synthetic datasets generated
from simulation tools»).

Симулятор воспроизводит процессы, известные из практики регионального развоза:

| Фактор | Как реализован |
|---|---|
| Суточный профиль | Пик 06:00–10:00 (утренний развоз в магазины) и 14:00–17:00, ночью почти ноль |
| Недельная сезонность | Пик в понедельник и пятницу — завоз в торговлю, провал в воскресенье |
| Годовая сезонность | Строительный сезон апрель–октябрь тянет вверх направления с высокой долей стройматериалов |
| Погода | AR(1)-модель ветра: пыльная буря при >15 м/с сажает активность на 30–50%; жара выше 40 °C бьёт по скоропорту |
| Праздники РК | Торговля не завозит, спрос падает на 55% |
| Размер НП | Базовый спрос пропорционален населению точки назначения, сублинейно |
| Инциденты | Перекрытие трассы, занос песком — **латентный** фактор, в датасет не пишется |

Инциденты специально не попадают в признаки: это честный источник
неустранимого шума, из-за которого R² не может быть близок к единице.

## Метрики

Валидация — временной сплит без утечки: последние 3 месяца в тест.
Бейзлайн — климатология по (направление, день недели, час), то есть
среднее историческое значение. Модель обязана его обыграть.

| Метрика | Модель | Бейзлайн hour-of-week |
|---|---|---|
| MAE | **0.34** | 0.36 |
| RMSE | **0.46** | 0.52 |
| R² | **0.907** | 0.880 |

Трейн 153 120 наблюдений, тест 24 480.

**Честная оговорка.** Выигрыш над бейзлайном скромный: календарь сам по себе
объясняет большую часть спроса на развоз. Модель добавляет годовую сезонность
и погоду — бейзлайн их не видит в принципе. Наибольшая разница проявляется
в дни пыльных бурь и в переходы строительного сезона.

## Признаки

```
hour_sin, hour_cos      час по времени Актау (UTC+5), циклическое кодирование
dow, is_weekend         день недели, Пн=0 как в pandas
doy_sin, doy_cos        день года — годовая сезонность
wind_ms, temp_c         ветер и температура
is_holiday              праздничный день РК
dir_*                   one-hot по 10 направлениям
```

На проде `wind_ms` и `temp_c` приходят из **реального** прогноза Open-Meteo
для района Актау (`lib/weather.ts`, без ключа). При недоступности сервиса
используется климатологический фолбэк.

## Паритет Python ↔ TypeScript

Порядок и кодировка признаков в `lib/forecast.ts` обязаны бит-в-бит совпадать
с `build_features()` в `train.py`. Расхождение здесь — самый неприятный вид
бага: модель та же, а прогноз другой.

```bash
.venv/Scripts/python parity_check.py   # инференс по JSON на стороне Python
node ../ml/parity-check.ts             # тот же JSON через lib/forecast.ts
```

Пять контрольных случаев: утренний пик, ночь, праздник РК, пыльная буря,
воскресенье с жарой. Значения совпадают в пределах округления.

## Воспроизведение

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt

.venv/Scripts/python generate_dataset.py   # → data/direction_demand.csv
.venv/Scripts/python train.py              # → метрики, графики, lib/forecast-model.json
.venv/Scripts/python parity_check.py       # сверка с TypeScript
```

Графики сохраняются в `ml/figures/`: факт против прогноза за тестовое окно
и важность признаков.
