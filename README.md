## Проблема

Мангистауская область — 165 642 км² с разбросанными посёлками. Магазины, стройки и фермы
возят грузы внутри региона, но цифровых инструментов для этого нет: машину ищут звонками
и в мессенджерах, а перевозчик после разгрузки возвращается **пустым**.

Порожний возврат Актау → Жанаозен на тенте 20 т стоит перевозчику **23 712 ₸** — это только
топливо и время водителя. При ставках биржи DELLA сам рейс приносит 62–116 тыс. ₸, то есть
порожний возврат съедает **20–38% выручки**.

## Решение

**Биржа с автоматическим матчингом обратной загрузки.** В момент, когда перевозчик открывает
заявку, система уже нашла ему встречный груз и показывает в тенге, сколько он сэкономит,
если возьмёт связку.

Ни одна казахстанская платформа — ATI.SU, Della, Fa-Fa, CMR24, Jukter, Tasyma, inDrive —
этого не делает. Максимум там ручной фильтр «попутный груз».

```
Заявка Актау → Жанаозен, продукты, рефрижератор
   ↓
Система подбирает машину и сразу ищет встречный груз
   ↓
Найден: рыбная продукция Жанаозен → Актау, подача 0 км
   ↓
Порожний пробег 151 км → 0 км · Экономия 25 445 ₸
```

| Требование кейса | Реализация |

| Демо ключевого сценария | Отправитель создаёт заявку → перевозчик видит её в реальном времени → берёт связку |
| Экономическое обоснование | Расчёт экономии в каждой заявке, калькулятор масштаба для акимата |

| Средняя ЗП по области | 608 400 ₸/мес | БНС, I кв. 2026 |

| Ставки перевозки | 417–778 ₸/км | биржа DELLA |

**Чего мы не выдумывали.** По Казахстану исследований порожнего пробега не существует —
Kazlogistics прямо констатирует отсутствие статистики, поэтому взят европейский бенчмарк.
Объём перевозок по области в тоннах БНС не публикует. Население большинства сёл — оценка
OSM с отставанием 10–50%, используется только как порядок величины.

## Проверка расчётов

Обе проверки воспроизводимы и лежат в репозитории:

```bash
node scripts/check-economics.ts   # сверка с эталоном ТЗ: 23 908 ₸ против 23 712 ₸, 0.83%
npx tsx scripts/check-matching.ts # матчинг на реальных данных из БД
```

`check-matching.ts` тянет справочник и матрицу из Supabase, собирает заложенную пару заявок
и проверяет, что алгоритм находит связку, отбрасывает встречный груз не в ту сторону
и предпочитает машину с нулевой подачей.

## Машинное обучение

Прогноз спроса на перевозки по 10 направлениям области на 48 часов вперёд.

- **Задача:** число заявок в час по направлению
- **Модель:** GradientBoostingRegressor (scikit-learn), 220 деревьев, обучение своё
- **Признаки:** час и день недели по времени Актау, годовая сезонность, ветер, температура, праздники РК, one-hot направления
- **Данные:** симулятор `ml/generate_dataset.py` — 177 600 почасовых наблюдений за 2 года
- **Валидация:** временной сплит без утечки, последние 3 месяца в тест

| Метрика | Модель | Бейзлайн hour-of-week |
|---|---|---|
| MAE | **0.34** | 0.36 |
| RMSE | **0.46** | 0.52 |
| R² | **0.907** | 0.880 |

Выигрыш над бейзлайном скромный и мы это не прячем: календарь сам по себе объясняет
большую часть спроса, модель добавляет сезонность и погоду. На входе — **реальный** прогноз
Open-Meteo для района Актау, не синтетика.

Инференс переписан на TypeScript (`lib/forecast.ts`): деревья экспортируются в JSON,
прогноз считается прямо в route handler на Vercel, отдельный Python-сервис в проде не нужен.
Паритет Python ↔ TypeScript проверяется на пяти контрольных случаях (`ml/parity_check.py`).

**Как это используется:** на дашборде перевозчика видно, где не хватает машин.
Дефицит считается через оборачиваемость — на плече Актау — Курык машина успевает
2.6 рейса в сутки, а до Бейнеу не успевает и одного круга.

## Технологический стек

```
Next.js 16.2.6, React 19.2.4, TypeScript 5.7.3
@supabase/ssr + supabase-js  — БД, auth, realtime, RLS
@2gis/mapgl 1.73             — карты
Groq API → Llama 3.3 70B     — объяснение расчёта словами
Tailwind 4 + shadcn/ui       — UI
Recharts 2.15                — графики
scikit-learn                 — обучение модели
Vercel                       — деплой, регион fra1
```

**Про ИИ честно.** LLM не считает и не подбирает — все числа считает наш код
(`lib/matching.ts`, `lib/economics.ts`) по данным из БД. Groq получает готовый результат
и только формулирует его водителю на русском. Без `GROQ_API_KEY` продукт работает
полностью, объяснение просто собирается шаблоном.

## Экономический эффект

Калькулятор на дашборде акимата считает вживую. При 10% активных перевозчиков,
среднем плече 120 км и 1.5 рейсах в день:

```
активных машин       = 18 795 × 10%              = 1 880
порожних км/сутки    = 1 880 × 1.5 × 0.258 × 0.20 × 120 км = 17 457 км
экономия ₸/сутки     = 17 457 × 0.30 л/км × 340 ₸ = 1 780 593 ₸
```

Около **650 млн ₸ в год** только на топливе, не считая износа техники и времени водителей.

## Быстрый старт

```bash
pnpm install
cp .env.example .env.local   # заполнить ключи Supabase, 2GIS, Groq
pnpm dev
```

Миграции применяются в Supabase SQL Editor в порядке: `schema.sql`,
`migration_add_roles.sql`, `migration_add_order_details.sql`, `migration_land_routes.sql`,
`migration_billing.sql`, `migration_dispatcher_access.sql`, `migration_regional.sql`.

Затем один раз посчитать матрицу расстояний:

```bash
node scripts/seed-distances.ts   # 105 запросов к OSRM, ~2 минуты
```

Скрипт запускается **один раз**, результат лежит в БД. Во время демо обращений
к OSRM не происходит — публичный сервер держит 1 запрос в секунду и на сцене бы отвалился.

## Схема базы данных

```sql
settlements(id, name, name_kz, district, lat, lng, population, is_remote)
distance_matrix(from_id, to_id, km, minutes, geometry, approximate)
profiles(id → auth.users, full_name, role, company, phone)
orders(id, user_id, order_number, cargo_type, status, weight, volume,
       from_settlement_id, to_settlement_id, body_type, pickup_from, pickup_to,
       carrier_id, matched_backhaul_id, distance_km, empty_km_saved, tenge_saved)
vehicles(id, user_id, vehicle_code, plate, driver, status,
         body_type, capacity_kg, current_lat, current_lng, home_settlement_id)
land_routes(id, route_code, from_city, to_city, waypoints jsonb, progress)
customers(id, user_id, name, city, orders_count, status, revenue)
```

RLS включён везде. Ключевое для биржи: перевозчик видит **чужие** свободные заявки —
без этого матчинга не будет.

## Что осталось за рамками хакатона

- Интеграция с 1С и электронными накладными
